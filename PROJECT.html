bibliome-mcp

An MCP server that lets any MCP client (Claude Code, Claude Desktop, Codex) search and ask questions over the user's local Bibliome PDF library. Python package, public on PyPI.

2 · Tools

Tool What it does
search_library(q, k=20, folder=None) Semantic search over the local library; up to k passages
ask_library(q, k=5, folder=None) An on-device RAG answer grounded in the PDFs; needs the ask-mlx or ask-ollama extra
library_status() Whether Bibliome.app and an embeddings.db were found, plus a live engine health check

folder (optional, an absolute path inside the library) scopes either search tool to the documents under that folder. A missing or empty folder is an error, never a silent fall-back to searching everything.

3 · How it works

It does not index anything and does not vendor Bibliome's code. On the first tool call it adds Bibliome.app/Contents/Resources/pdf_organizer (plain Python source shipped in every install) to sys.path and calls the engine's own Index/dispatch in-process, pointed at the user's embeddings.db. So results match what the app itself would give.

It is deliberately NOT a subprocess bridge to Bibliome's bundled interpreter: that binary carries com.apple.security.inherit, so the sandbox kills it when anything but Bibliome.app launches it.

It leaves a status file (mcp-status.json) so Bibliome can show whether a client is connected.

Variable What it does
